# AI 工作记忆工作台｜MVP 产品需求与开发说明

> 历史归档：本文件描述早期 Mac 配合方案，不是当前安装或实现指令。当前采用 iPhone 独立使用方案，请以 [PRD.md](PRD.md)、[安装教程](INSTALL.md) 和用户最新要求为准。

> 版本：V1.0\
> 用途：可直接交给 Codex 作为项目开发依据\
> 产品定位：个人自用的 iPhone 场景录音 + Mac 本地 AI 工作记忆系统\
> 核心原则：录音先本地保存；用户结束录音并主动发起分析后，才将音频发送到
> Mac 本地工作台，并由 Mac 调用配置好的 AI 服务。

------------------------------------------------------------------------

## 1. 项目目标

开发一套个人工作记忆系统，帮助用户把会议、客户交流、工作讨论、灵感记录等真实语音，沉淀为可检索的文字、经验知识和自媒体内容素材。

系统不是"全天偷偷录音"的工具，而是由用户主动开启、主动停止、清晰显示录音状态的场景录音工具。第一版以按会议和工作场景分段录音为主，不追求全天自动录音。

### 1.1 第一版必须实现的闭环

1.  用户在 iPhone 上新建一个录音场景。
2.  用户主动点击开始录音。
3.  手机锁屏或切换到其他 App 后，录音在系统允许的条件下继续运行。
4.  用户暂停、继续或结束录音。
5.  音频首先保存在 iPhone 本地；录音过程中不上传音频。
6.  用户点击"结束并分析"后，App 尝试将音频传到用户自己的 Mac
    本地工作台。
7.  Mac 本地工作台调用配置的语音转写服务，将音频转成文字。
8.  大模型基于转写文本提取摘要、关键观点、决策、案例、待办和自媒体选题。
9.  用户可以查看原始转写、回听音频、编辑 AI
    结果、收藏内容、搜索历史记录。
10. 所有结果默认保存在 Mac
    本地；用户可按需删除原始音频、转写文本和分析结果。

### 1.2 第一版暂不做

-   全天自动启动录音或隐蔽录音。
-   自动识别所有说话人的真实身份。
-   自动发布小红书、视频号、抖音等平台内容。
-   多人团队账号、角色权限和企业级协同。
-   复杂的知识图谱、自动建立人与人的关系网络。
-   录音实时转写、实时 AI 总结或实时联网搜索。
-   云端账号体系、云端数据库、云端文件存储。
-   复杂的订阅、支付和商业化功能。
-   以 AI 生成结果替代用户审核。

## 2. 产品使用原则

1.  **用户明确控制录音。**
    开始、暂停、继续、结束均由用户操作；录音时显示明显状态。
2.  **本地优先。** 音频首先写入 iPhone 本地文件，不因网络不可用而丢失。
3.  **分析必须主动触发。**
    不在录音过程中自动上传音频。用户选择"结束并分析"后才进入传输与分析流程。
4.  **断网可录，联网再传。** Mac 未启动、Wi-Fi
    不可用或服务暂时不可达时，录音仍保留在手机，并标记为"待传输"。
5.  **所有 AI 结论可追溯。**
    重要观点和选题尽可能关联原文片段、时间戳及原始录音。
6.  **AI 生成内容必须可编辑。** AI 结果默认是草稿，不自动发布。
7.  **不将 API 密钥放在 iPhone 客户端。** 所有 AI 服务凭证保存在 Mac
    本地服务端。
8.  **隐私透明。** 首次使用说明麦克风用途、录音保存位置、AI
    分析时哪些数据会发给外部服务；录制他人前由用户确保取得必要告知和授权。

## 3. 推荐技术架构

采用"iPhone 原生录音 App + Mac 本地处理服务 + Mac 浏览器工作台"的架构。

### 3.1 iPhone 原生 App

-   语言与 UI：Swift + SwiftUI。
-   音频采集：AVFoundation；优先评估
    `AVAudioRecorder`，如分段保存、异常恢复或录音质量需要更强控制，再评估
    `AVAudioEngine`。
-   后台录音：正确配置 `AVAudioSession`，并在 Xcode Target 的 Background
    Modes 中启用 Audio。必须遵守 iOS 系统录音权限和音频中断规则。
-   本地文件：应用沙盒中的 Application Support / Recordings
    目录；音频文件使用 AAC 编码的 M4A 格式。
-   元数据：本地 JSON
    或轻量数据库记录场景、文件路径、时长、状态、创建时间和传输状态。
-   本地队列：维护待上传列表；传输失败时允许重试。
-   网络传输：与 Mac
    本地服务配对后，通过同一可信局域网传输。实现配对认证、上传校验和重复上传防护；不开放公网端口。
-   权限：请求麦克风权限；访问局域网时提供清楚的用途说明。

### 3.2 Mac 本地服务

-   后端：Python + FastAPI。
-   数据库：SQLite。
-   文件存储：Mac 本地项目数据目录，按日期与录音 ID 分层。
-   配置：`.env` 或 macOS Keychain 保存 AI
    服务配置；严禁将真实密钥提交到 Git。
-   转写服务：通过独立的 `TranscriptionProvider`
    接口接入，第一版先实现一种可配置的语音转写服务。
-   大模型服务：通过独立的 `LLMProvider`
    接口接入，第一版先实现一种可配置的大模型服务。
-   任务处理：本地后台任务队列，保存任务状态，支持失败重试。
-   运行方式：用户手动启动 Mac
    本地服务；服务仅监听本机与指定局域网接口，不使用公网服务器、不配置路由器端口转发。
-   安全：优先使用 TLS 加密局域网传输，并在 iPhone
    配对时校验服务证书指纹；若第一版开发阶段暂时无法稳定实现
    TLS，必须将未加密传输标为开发限制，仅允许可信私人 Wi-Fi
    测试，不得宣称传输安全，也不得用于敏感录音的正式使用。

### 3.3 Mac 浏览器工作台

-   前端：React + TypeScript +
    Vite（如仓库已有成熟技术栈，优先沿用现有栈，不要无故重建）。
-   使用方式：Mac 本机浏览器打开本地工作台。
-   前端只访问 Mac 本地 FastAPI，不直接持有 AI API Key。
-   UI 重点：录音列表、转写详情、AI 分析、选题库、搜索、设置、数据删除。
-   第一版不需要账号注册、登录服务器或云端同步。

### 3.4 数据流

``` text
iPhone 用户主动开始录音
        ↓
音频写入 iPhone 本地 M4A 文件
        ↓
用户主动结束录音
        ↓
选择“仅保存”或“结束并分析”
        ↓
如选择分析：iPhone 将音频传输到 Mac 本地服务
        ↓
Mac 本地保存原始音频并创建分析任务
        ↓
语音转写服务处理音频
        ↓
转写文本保存到 Mac SQLite / 本地文件
        ↓
大模型提取摘要、判断、案例、待办和选题
        ↓
结果保存到本地工作台，用户审核、编辑、收藏或删除
```

说明：如果选择云端语音转写或云端大模型，分析所需的音频或文本会发送给对应服务商。第一版必须在设置页说明这一点，并在用户触发分析前进行明确提示。

## 4. 功能需求

### 4.1 iPhone 端：录音首页

首页应简洁，优先保证录音可靠和操作明确。

显示内容： - 当前录音状态：未录音 / 正在录音 / 已暂停 / 待传输 / 分析中
/ 已完成 / 失败。 - 大号"开始录音"按钮。 - "新建场景"入口。 -
最近录音列表。 - 待传输数量与最近一次传输结果。 -
剩余存储空间提示（如系统允许获取）。

开始录音前，用户填写： - 录音标题（必填，可自动生成默认标题）。 -
场景类型：会议、客户沟通、头脑风暴、工作复盘、灵感记录、培训学习、其他。 -
关联项目或标签（可选）。 - 备注（可选）。

默认标题示例：`2026-10-22 09:30 客户沟通`。

### 4.2 iPhone 端：录音控制

录音页面显示： - 录音标题和场景类型。 - 正在录音的明显视觉状态。 -
已录时长。 - 暂停 / 继续按钮。 - 结束录音按钮。 -
音量活动指示（仅作辅助，不承诺准确判断讲话内容）。 -
存储空间或异常提示。

行为要求： - 首次录音前请求麦克风权限，并解释用途。 - 录音期间锁屏或切换
App 后，在 iOS 允许的条件下持续录音。 - 正确处理电话、Siri、闹钟、其他
App 抢占音频、耳机插拔等音频会话中断。 -
发生音频中断时记录事件和时间，显示醒目的状态，不得假装仍在录音。 -
录音暂停时不应继续采集音频。 -
点击结束后必须关闭并落盘文件，再进入后续流程。 -
录音文件应分段保存或具备可靠的恢复机制，避免单一超长文件损坏导致整段内容丢失。 -
推荐先按约 10--15
分钟生成一个音频分段文件，并将分段归属于同一个录音场景；该间隔应可配置。 -
切分音频时应记录每个分段的开始时间、结束时间、顺序和文件校验信息。 - 若
App
被系统终止或异常退出，重新打开时应检查未完成录音，恢复可用文件并提示用户确认。 -
录音中禁止自动上传音频。 - 结束后提供两个明确选项： 1. **仅保存到手机**
2. **结束并分析**（连接 Mac 后传输）

### 4.3 iPhone 端：录音列表与详情

录音列表支持： - 按时间倒序查看。 - 按标题和场景类型筛选。 -
显示日期、时长、状态、传输状态。 - 删除录音前二次确认。 -
查看待传输、传输失败、分析完成等状态。

录音详情支持： - 编辑标题、类型、标签和备注。 - 播放本地音频。 -
查看音频分段。 - 重新上传失败任务。 - 删除手机本地音频。 -
明确区分"删除手机文件"和"删除 Mac 端副本"。

### 4.4 iPhone 与 Mac 配对、传输

Mac 本地服务启动后，在 Mac 工作台中显示配对二维码或短配对码。用户在
iPhone 中扫描或输入配对码完成绑定。

需求： - 显示 Mac 服务是否可用。 - 显示最近连接时间。 - 支持解除配对。 -
传输前检查录音 ID，防止重复创建同一条录音。 -
分段文件逐个传输，并校验文件大小与 SHA-256 摘要。 -
支持中断后续传；已经成功接收的分段不重复上传。 -
上传失败时保留手机原始文件，并显示失败原因和重试按钮。 - Mac
未运行或不在同一局域网时，录音保持"待传输"状态。 -
不允许从公网访问本地服务；不要求用户购买云服务器。 - iPhone
需要局域网权限时，使用清晰说明，例如"用于将录音安全传输到你自己的 Mac
本地工作台"。

### 4.5 Mac 工作台：录音库

录音列表显示： - 标题、日期、场景类型、时长。 - 音频是否已接收。 -
转写状态。 - AI 分析状态。 - 标签与关联项目。

支持： - 标题、正文、标签和日期搜索。 - 按场景类型筛选。 -
查看原始音频和播放。 - 查看转写全文。 - 重新转写。 - 重新分析。 -
编辑标题、备注和标签。 - 删除单条录音及关联数据。 - 导出转写文本为
Markdown / TXT。 - 导出 AI 分析结果为 Markdown。 - 对删除进行二次确认。

### 4.6 语音转写

处理流程： 1. 检查音频文件是否完整。 2.
检查文件格式、时长和大小是否满足所选转写服务的限制。 3.
如超出服务限制，按分段文件分别转写，再按时间顺序合并。 4.
保存原始转写文本。 5. 尽可能保留分段起止时间、段落时间戳和原始分段 ID。
6. 对转写失败的分段提供单独重试，不重复处理已成功分段。 7.
转写结果需允许人工编辑，编辑后的版本与原始 AI 转写应有清楚区分。 8.
对听不清或识别不确定的内容，不应擅自补全为确定事实。

第一版不强制实现说话人分离。如果转写服务能提供说话人标签，可以作为可选字段；不能识别时不得编造发言人身份。

### 4.7 AI 分析

转写完成后，用户点击"生成分析"或"结束并分析"自动进入分析队列。

每份录音生成以下内容：

1.  **一句话摘要**：概括本次谈话或工作记录的核心。
2.  **内容摘要**：按主题分段总结，尽量保留重要背景。
3.  **关键观点**：记录用户表达的观点与主张。
4.  **判断逻辑**：提取"观察到什么---依据是什么---为什么这样判断---最后如何选择"。
5.  **案例记录**：问题背景、采取的行动、关键做法、结果、可复用经验；没有结果时明确标记"结果尚未确认"。
6.  **决策与理由**：区分已做出的决定、备选方案和仍待讨论的事项。
7.  **待办事项**：任务、可能的负责人（仅在录音中明确时填写）、截止时间（仅在明确时填写）、原文依据。
8.  **待跟进问题**：尚未解决或需要验证的事项。
9.  **自媒体选题**：从真实观点、反常识判断、典型问题、经验案例中生成选题。
10. **口播初稿**：用户选中某个选题后再生成，不要求每条录音都自动生成长篇文案。

### 4.8 自媒体选题生成规范

每个选题至少包括： - 选题标题。 - 目标受众。 - 核心冲突或问题。 -
核心观点。 - 可用的真实案例或原文依据。 - 推荐表达角度。 -
关联录音和原文时间戳。 - 内容状态：待审核 / 已收藏 / 已写成稿 / 已放弃。

选题生成原则： - 不追求数量堆积，优先推荐 3--8 条有依据的选题。 -
不把普通工作流水账强行包装成观点。 -
不凭空增加人物、数据、案例、结论或结果。 -
允许一条录音没有合适选题，并明确显示"本次没有足够有价值的选题"。 -
同一观点尽量去重；如果与历史选题高度相似，提示用户已有相似内容。 -
选题应符合用户的内容方向：AI 落地、企业经营、工作方法、经验萃取、老板 IP
与真实工作观察。 -
口播初稿保持口语化；优先引用用户原有表达，再进行结构整理。 -
不自动发布任何内容。

### 4.9 AI 分析页面

采用标签页或清晰分区展示： - 摘要 - 关键观点 - 判断与方法 - 案例 -
决策与待办 - 自媒体选题 - 原始转写 - 原始录音

所有 AI
内容可编辑、复制、收藏、删除或导出。重要观点应尽可能提供"查看原文"入口，跳转至相应转写片段，并支持播放对应音频片段（若时间戳可用）。

### 4.10 设置

提供以下设置： - Mac 本地数据目录。 - AI 服务提供商与模型配置。 - API
Key 配置状态（不在界面中明文回显完整密钥）。 - 转写服务配置。 -
自动分段时长。 - 默认录音场景。 - 本地保留策略。 -
是否在分析完成后自动清理 Mac
端临时上传文件（默认不自动删除原始音频，需用户主动选择）。 -
录音文件总大小和剩余磁盘空间。 - 数据导出与完整删除。 - 隐私说明。 -
服务连接状态与日志。

## 6. 数据模型建议

实际字段可由 Codex 根据实现方式调整，但必须保留下列核心信息。

### 6.1 Recording（录音场景）

-   `id`: UUID
-   `title`: 标题
-   `scene_type`: 场景类型
-   `tags`: 标签
-   `notes`: 备注
-   `started_at`: 开始时间
-   `ended_at`: 结束时间
-   `duration_seconds`: 时长
-   `device_status`: 手机文件状态
-   `transfer_status`: 待传输 / 传输中 / 已传输 / 失败
-   `transcription_status`: 待转写 / 转写中 / 已完成 / 失败
-   `analysis_status`: 待分析 / 分析中 / 已完成 / 失败
-   `created_at`, `updated_at`

### 6.2 AudioSegment（音频分段）

-   `id`: UUID
-   `recording_id`: 所属录音
-   `sequence_number`: 分段序号
-   `local_file_path`: 本地路径
-   `start_offset_seconds`: 相对录音起始时间
-   `duration_seconds`: 分段时长
-   `file_size_bytes`: 文件大小
-   `sha256`: 文件校验摘要
-   `transfer_status`: 传输状态
-   `transcription_status`: 转写状态
-   `error_message`: 最近一次错误

### 6.3 Transcript（转写）

-   `id`: UUID
-   `recording_id`: 所属录音
-   `segment_id`: 对应音频分段（允许为空）
-   `text_original`: 原始 AI 转写
-   `text_edited`: 人工修订文本（允许为空）
-   `start_time_seconds`: 起始时间（可为空）
-   `end_time_seconds`: 结束时间（可为空）

## 7. API 设计建议

Mac FastAPI 提供本地 API。路由名称可调整，但功能必须覆盖：

-   `GET /api/health`：健康检查。
-   `POST /api/pairing/start`：创建短时有效的配对流程。
-   `POST /api/pairing/complete`：完成设备配对。
-   `GET /api/recordings`：录音列表与筛选。
-   `POST /api/recordings`：创建录音元数据。
-   `GET /api/recordings/{id}`：录音详情。
-   `POST /api/recordings/{id}/segments`：上传音频分段。
-   `GET /api/recordings/{id}/segments`：查询分段状态。
-   `POST /api/recordings/{id}/transcribe`：发起转写。
-   `POST /api/recordings/{id}/analyze`：发起 AI 分析。
-   `GET /api/jobs/{id}`：查询任务状态。
-   `GET /api/recordings/{id}/transcript`：获取转写结果。
-   `GET /api/recordings/{id}/analysis`：获取分析结果。
-   `GET /api/ideas`：选题列表与筛选。
-   `PATCH /api/ideas/{id}`：修改选题与状态。
-   `POST /api/ideas/{id}/draft`：生成或重写口播初稿。
-   `GET /api/search?q=...`：全文搜索。
-   `POST /api/export/markdown`：导出 Markdown。
-   `DELETE /api/recordings/{id}`：删除录音及用户确认要删除的关联数据。

要求： - 对重复请求保持幂等性，避免重复创建录音或重复扣费。 -
上传接口校验设备配对令牌、文件大小、文件类型和摘要。 -
对任务提供可读状态、失败原因和重试机制。 - API Key 只能存在于 Mac
服务端配置中。 - 本地服务不开放公网访问。 - 错误日志不得记录 API
Key、完整敏感转写文本或不必要的音频内容。

## 9. 异常与恢复要求

必须处理以下情况：

1.  用户拒绝麦克风权限。
2.  录音过程中来电或其他音频中断。
3.  用户暂停后忘记继续录音。
4.  手机存储空间不足。
5.  App 被系统终止或异常退出。
6.  单个音频分段写入失败。
7.  Mac 未开机或服务未启动。
8.  iPhone 与 Mac 不在同一局域网。
9.  上传中断或重复上传。
10. 语音转写服务失败、限流或超出文件限制。
11. 大模型调用失败或返回不可解析结果。
12. 用户误删文件或删除了仍在分析的录音。
13. Mac 磁盘空间不足。
14. AI 服务 API Key 缺失或失效。

处理原则： - 明确展示失败状态，不得静默失败。 -
失败时保留已有原始文件。 - 可重试的步骤提供重试入口。 -
任务状态持久化，重启服务后能继续处理。 -
不重复执行已成功完成且可能产生费用的步骤，除非用户明确要求重跑。 -
删除数据前进行二次确认，并说明会影响哪些本地文件和分析结果。

## 10. 隐私与安全要求

1.  首次启动展示隐私说明，并请求必要权限。
2.  录音必须由用户主动开启，页面清楚显示正在录音。
3.  不在录音过程中上传音频。
4.  只有用户点击"结束并分析"后，才向 Mac 传输音频。
5.  发往第三方 AI
    服务前明确告知：将发送音频或转写文本、服务商可能如何处理数据，以及可选的本地处理方式（若实现）。
6.  API Key 保存在 Mac 本地，不写入前端构建文件、不写入 iOS
    App、不提交到 Git。
7.  Mac 服务默认只供本机和已配对设备访问；不做公网端口映射。
8.  局域网传输优先采用 TLS 与配对认证。
9.  数据目录权限应限制为当前用户可访问。
10. 提供完整数据导出与删除功能。
11. 日志只记录必要的运行信息，避免写入敏感音频或完整转写文本。
12. 录制会议、客户沟通或其他人员声音时，用户需自行确保符合适用法律、公司制度及相关人员的告知与授权要求。

## 11. 非功能要求

-   **可靠性优先：** 录音和文件落盘优先于花哨 UI。
-   **弱网可用：** 录音不依赖网络；上传失败不影响本地录音。
-   **可恢复：** App 和 Mac 服务重启后恢复任务状态。
-   **可追溯：** 重要 AI 结论关联原文依据；不确定内容明确标注。
-   **可编辑：** 所有摘要、观点、选题和口播稿可人工修改。
-   **可迁移：** 本地文件采用通用音频和文本格式，支持导出。
-   **可维护：** 转写与大模型通过 Provider 接口解耦，便于替换服务商。
-   **可测试：**
    录音服务、文件队列、上传、转写、分析和删除逻辑均有测试。

## 12. MVP 验收标准

### A. iPhone 录音

-   [ ] 首次使用能正确申请麦克风权限。
-   [ ] 可以创建不同场景的录音。
-   [ ] 可以开始、暂停、继续和结束录音。
-   [ ] 锁屏 30 分钟测试期间，录音在未发生系统中断的情况下持续运行。
-   [ ] 录音过程中不上传音频。
-   [ ] 音频按配置的时长分段保存，并能按顺序播放。
-   [ ] 发生中断时能显示并记录状态。
-   [ ] 手机无网络或 Mac 关闭时，录音仍可本地保存。
-   [ ] App 重启后仍能查看已保存录音和待传输任务。

### B. Mac 接收与转写

-   [ ] iPhone 可以与 Mac 完成配对。
-   [ ] 音频分段可上传并通过校验。
-   [ ] 上传失败后可重试，不重复创建录音。
-   [ ] 转写成功后可以查看完整文字。
-   [ ] 长录音可分段转写并按顺序合并。
-   [ ] 转写失败时能看到错误并重试。

### C. AI 分析与选题

-   [ ] 每条已转写录音可主动发起 AI 分析。
-   [ ] 生成摘要、观点、判断逻辑、案例、待办和待跟进事项。
-   [ ] 能生成有原文依据的自媒体选题，或明确说明没有足够素材。
-   [ ] 选题可编辑、收藏、标记为已成稿或放弃。
-   [ ] 选题可查看来源录音和相关原文。
-   [ ] 可以基于选题生成口播初稿。
-   [ ] 不会自动发布内容。

### D. 数据与安全

-   [ ] 原始音频和数据库保存在用户指定的 Mac 本地目录。
-   [ ] API Key 不出现在 iPhone 客户端、前端代码或 Git 仓库中。
-   [ ] 没有配置公网服务器或公网端口转发。
-   [ ] 可以导出 Markdown / TXT。
-   [ ] 可以删除单条录音及其关联数据。
-   [ ] 删除操作有明确确认。
-   [ ] Git 忽略录音、数据库、密钥和运行数据。
-   [ ] 设置页明确说明使用云端 AI 时会发送哪些数据。

### E. 实际长录音测试

在正式用于重要工作前，至少完成： - \[ \] 30 分钟锁屏录音测试。 - \[ \]
60 分钟连续录音测试。 - \[ \] 经过来电或模拟音频中断后的恢复测试。 - \[
\] Wi-Fi 断开后继续录音、恢复网络后传输测试。 - \[ \] Mac
服务重启后继续处理待办任务测试。 - \[ \]
检查录音文件完整性、时长、播放质量和实际耗电情况。

以上测试通过前，不应承诺"任何情况下都不会中断"或直接将其用于不可重录的重要场景。
